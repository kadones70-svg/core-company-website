CORE COMPANY BLOG 구현 보고서
작성일: 2026-08-06
작업 위치: blog-app/

1. 구현 완료 범위

Astro 7.1.6 정적 사이트를 site=https://corecompany.net, base=/blog, output=static으로 구현했습니다.

구현 페이지와 산출물:
/blog/ 메인
/blog/articles/[slug]/ 글 상세
/blog/category/[category]/ 6개 카테고리
/blog/tag/[tag]/ 태그 아카이브와 빈 상태
/blog/search/ Pagefind 검색과 결과 없음 상태
/blog/editorial-policy/ 저자·편집 원칙
/blog/404.html 블로그 전용 404
/blog/rss.xml RSS
/blog/sitemap-index.xml 및 sitemap 파일
/blog/robots.txt

메인에는 Header, Hero, 검색과 대표 글, 산업별 시작, Editor's Pick, 최신 글, 6개 주제, 다크 문의 CTA, Footer를 구현했습니다. 글 상세에는 breadcrumb, 메타 정보, 태그, 모바일/데스크톱 목차, 본문, callout, 표, 체크리스트, 출처, 변경 이력, 작성·검수·AI 공개, 관련 글, 문의 CTA를 구현했습니다.

모바일 메뉴에는 aria-expanded, aria-controls, 첫 메뉴 포커스 이동, Escape 닫기, 포커스 복귀와 메뉴 안 포커스 순환을 구현했습니다. 390px, 1024px, 1440px 기준 반응형을 적용했습니다.

2. 콘텐츠 시스템

Astro 7 Content Layer의 glob loader와 astro/zod 스키마를 사용했습니다. Markdown 기본 구조와 sample 게시글 3개를 만들었습니다. sample 3개는 모두 draft:false, sample:true이며 실제 고객 사례가 아니라는 안내를 포함합니다.

production build는 draft와 sample을 제외합니다. review build만 sample을 포함합니다. 현재 실제 게시 가능한 sample:false 글이 없으므로 최종 production의 글 상세, RSS 항목, Pagefind 공개 검색 결과는 0개입니다. 이는 필터 동작의 결과이며 실제 글을 작성·검수한 뒤 배포해야 합니다.

content:new, content:validate, content:list, image:optimize 명령을 구현했습니다. 잘못된 frontmatter와 중복 slug가 검증에서 차단되는 단위 테스트를 포함합니다.

3. 검색, SEO, 구조화 데이터

Astro build 후 Pagefind 1.5.2 색인을 생성합니다. 제목, summary, 본문, 카테고리, 태그를 검색하고 반복 navigation/footer/CTA는 제외합니다. /blog/ base에서 동적 Pagefind 모듈 경로를 사용합니다.

production에 공개 글이 0개일 때도 검색 번들이 존재하도록 빌드 중 임시 빈 색인을 만들고 원본 임시 HTML은 즉시 삭제합니다. 검색 UI에서도 내부 센티널 URL을 필터링하므로 사용자에게 노출되지 않습니다.

canonical, description, Open Graph, Twitter/X card, robots, sitemap, RSS, Article, Organization, BreadcrumbList JSON-LD를 구현했습니다. FAQ JSON-LD는 모든 글에 자동 삽입하지 않습니다.

4. 문의 출처 추적과 분석 준비

공통 buildContactUrl 유틸리티가 기존 #contact 앵커를 보존하고 source=blog, article, category, cta query parameter를 앵커 앞에 추가합니다. header, home, article-inline, article-bottom, category-bottom, tag-bottom, editorial-bottom, footer 등의 위치를 구분합니다.

선택적 trackEvent 어댑터 타입을 제공하며 gtag 또는 dataLayer가 없으면 아무 작업도 하지 않습니다. Measurement ID, Cloudflare 토큰, 개인정보는 추가하지 않았습니다. Cloudflare Web Analytics 활성화는 Hermes 배포 단계 작업으로 남겼습니다.

5. 접근성과 성능

skip link, semantic landmarks, heading 계층, time datetime, breadcrumb aria-label, 2px focus-visible, 44px 터치 타깃, reduced motion, 접근 가능한 검색 form, details 모바일 목차, 표/코드 내부 스크롤, 이미지 alt 검사를 구현했습니다.

axe 자동 검사에서 테스트한 페이지의 WCAG A/AA 위반이 없었습니다. 자동 검사만으로 접근성이 보장된다고 판단하지 않았으며 키보드 메뉴, focus 복귀, 가로 overflow, 목차와 표 동작을 Playwright로 별도 검사했습니다.

외부 웹폰트, 자동 재생 미디어, 대형 히어로 이미지, 프레임워크 클라이언트 island를 추가하지 않았습니다.

6. 승인 디자인 파일 탐색 결과

작업 시작 시 프로젝트 루트에는 .git 외에 V25 소스, 운영 /blog/ 폴더, approved_design, design-reference, references, _codex_input, 승인 PNG/HTML이 없었습니다. 따라서 승인 PNG나 HTML과 픽셀 단위 비교를 할 수 없었습니다.

디자인은 제공된 Paper Editorial + Calm Engineering 명세, 색상 토큰, 레이아웃 순서와 반응형 기준을 기준으로 구현했습니다. 승인 파일 미발견 때문에 발생한 명시적 차이는 없으나 승인 원본과의 시각 비교는 미수행입니다.

10. 기존 파일 변경 여부

기존 V25 홈페이지: 로컬 소스가 없었으며 변경하지 않았습니다.
현재 운영 /blog/ 폴더: 로컬 폴더가 없었으며 변경하거나 복사하지 않았습니다.
프로젝트 루트 기존 파일: 수정하거나 삭제하지 않았습니다.
Git: 명령을 사용하지 않았습니다.

Cloudflare/DNS/배포: 변경하거나 실행하지 않았습니다.
ZIP: 생성하지 않았습니다.
DB/CMS/회원/댓글/좋아요/공개 조회수/API: 구현하지 않았습니다.

11. 디자인 차이와 검수 화면

승인 디자인 파일이 없어 제공된 프롬프트 명세만 기준으로 구현했습니다. 큰 이미지 대신 경량 선형 편집 다이어그램을 사용했고, 다크 영역은 CTA와 Footer에 제한했습니다. 공식 SVG는 표시 성능을 위해 같은 자산의 WebP 복사본을 사용합니다.

review/에 요청된 13개 1440px, 1024px, 390px 검수 화면을 생성했습니다. 전체 페이지와 fold 이미지를 구분했습니다.

12. 미완료 범위와 남은 사용자 결정

기능 구현 미완료 항목은 없습니다.

운영 콘텐츠 결정이 필요합니다. 현재 3개 글은 모두 검수용 sample이며 production에는 공개 글이 없습니다. 배포 전에 실제로 검수된 sample:false Markdown 글을 최소 1개 이상 준비하고 작성자, 검수자, 출처, 변경 이력을 확정해야 합니다.

승인 디자인 원본이 제공되면 현재 review 스크린샷과 별도 시각 비교가 필요합니다.

13. 알려진 문제와 경고

로컬 실행 Node는 v26.5.1, npm은 12.0.2였습니다. 요구 배포 기준은 Node 24 LTS이므로 Hermes는 Node 24 LTS에서 npm ci와 npm run build를 다시 실행해야 합니다. package.json engines는 >=24 <27로 설정되어 있습니다.

Pagefind는 한국어 stemming을 지원하지 않는다는 경고를 출력합니다. 정확한 한글 검색어의 색인과 결과는 E2E에서 통과했지만 어근 변화까지 자동 확장하지는 않습니다.

npm 12는 esbuild 0.28.1 postinstall 스크립트가 allowScripts에 포함되지 않았다는 경고를 냈습니다. 현재 설치, Astro check, production/review build, Playwright, Lighthouse는 모두 성공했습니다.

Lighthouse는 production 홈과 편집 원칙 두 페이지만 측정했습니다. production에 공개 article이 없어 article Lighthouse 측정은 하지 않았습니다.

14. 배포 확인

Codex는 실제 운영 사이트, 기존 /blog/, Cloudflare Pages, DNS를 수정하지 않았고 배포를 수행하지 않았습니다. 배포 인계는 HERMES_DEPLOYMENT_HANDOFF.txt를 따릅니다.
